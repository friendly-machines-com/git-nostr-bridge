Bridge between Nostr and GitHub

Optional identity linking

This is the optional identity-linking page for the bidirectional bridge between NostrGit and its github.com mirror.

The bridge itself does not require you to authenticate. Issues, comments, status changes, and deletions cross in both directions regardless: unlinked GitHub authors are represented on Nostr by the clearly labelled bridge key, and unlinked Nostr authors are represented on GitHub by the organization bridge account with their Nostr author and event attributed.

Linking both identities only upgrades those proxy crossings: GitHub activity can be signed by your own Nostr signer, and Nostr activity can be posted using your own GitHub App user authorization. Standalone NostrGit posting continues to use nos2x (or another NIP-07 signer) directly.

Repository Stars are the one GitHub identity exception. GitHub only allows a user—not an App installation—to star a repository. A Nostr Star therefore reaches GitHub only when that exact Nostr author has linked a GitHub user; the Nostr Star itself never depends on this site.

Show your GitHub account on Nostr (optional)

This adds a verified GitHub link beside activity signed by your Nostr key. It is public profile information. It does not change your bridge link, permissions, or how content crosses.

  1. 1Create one GitHub Gist containing the proof below—for example, in a file named nostr.txt. The filename does not matter.
  2. 2Paste its URL and review the complete public identity list.
  3. 3Approve one identity update in Amber.
  4. 4The signed update is saved and published to Nostr relays.

Put this exact single line in the Gist’s only file:

Create public GitHub Gist

    The complete current list is preserved. Only the claim is added, replaced, or removed.

    Remove the public GitHub proof

    This republishes your complete identity list without this GitHub account. It does not unlink the bridge and does not delete the Gist.

    Why link both? Nostr side: your GitHub issues and comments get your cryptographic signature instead of the labelled bridge signature. Both verified halves are required only to join the identities, never to bridge the content.
